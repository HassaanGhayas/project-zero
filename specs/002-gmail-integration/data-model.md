# Data Model: Gmail Integration

**Version**: 1.0.0
**Status**: Specification
**Last Updated**: 2026-02-09

## Overview

This document defines all data entities and their schemas used in the Gmail Integration feature. All entities use YAML frontmatter for structured metadata and markdown for narrative content.

---

## Entity 1: Email Action File

**Purpose**: Represents a Gmail message awaiting review and action in the Obsidian vault

**Storage Location**: `AI_Employee_Vault/Needs_Action/FILE_<sender>_<subject_slug>.md` (when pending)

**Lifecycle**:
1. Created in `Needs_Action/` with status: pending
2. User edits YAML status field to "approved" or "rejected"
3. Status field watcher moves file to `Approved/` or `Rejected/`
4. Approved watcher executes action and moves to `In_Progress/`
5. Confirmation file created alongside in `In_Progress/`
6. Finally moves to `Done/` after confirmation

### YAML Frontmatter Schema

```yaml
---
type: email                           # Literal: "email" (distinguishes from invoice, task, etc.)
gmail_message_id: "18d4f3a2b1c9e7f6" # Gmail API message ID (unique identifier)
sender: "alice@example.com"           # Email from field
sender_name: "Alice Smith"            # Optional: parsed name if available
subject: "Project update for Q1"      # Email subject line
received_timestamp: "2026-02-09T14:30:00Z"  # ISO 8601 UTC timestamp
status: "pending"                     # Enum: pending | approved | rejected | archived
priority: "high"                      # Enum: high | medium | low (set by categorizer)
has_attachments: false                # Boolean: does message have attachments?
attachment_count: 0                   # Integer: number of attachments (0 if no attachments)
attachment_metadata:                  # Optional: list of attachments if present
  - filename: "report.pdf"
    size_bytes: 2048576
    is_large: true                    # true if > 10MB
category: "email"                     # Literal: "email" (or "email-financial" if financial)
suggested_actions:                    # List of recommended next steps
  - "Review and approve for archival"
  - "No urgent action required"
---
```

### Frontmatter Field Definitions

| Field | Type | Required | Description | Example |
|-------|------|----------|-------------|---------|
| type | string | ✅ | Entity type identifier | "email" |
| gmail_message_id | string | ✅ | Unique Gmail API ID | "18d4f3a2b1c9e7f6" |
| sender | string | ✅ | Email address (from field) | "alice@example.com" |
| sender_name | string | ❌ | Parsed human name | "Alice Smith" |
| subject | string | ✅ | Email subject line | "Project update" |
| received_timestamp | string | ✅ | ISO 8601 UTC | "2026-02-09T14:30:00Z" |
| status | enum | ✅ | Current workflow stage | "pending", "approved", "rejected" |
| priority | enum | ✅ | User attention level | "high", "medium", "low" |
| has_attachments | boolean | ✅ | Presence of attachments | true/false |
| attachment_count | integer | ✅ | Number of attachments | 0, 1, 2, ... |
| attachment_metadata | array | ❌ | Attachment details | [{filename, size_bytes, is_large}] |
| category | string | ✅ | Classification | "email", "email-financial" |
| suggested_actions | array | ✅ | Recommended next steps | ["Review", "Archive"] |

### Markdown Body Content

```markdown
## Email Snippet

> Email excerpt or summary (first 200 chars of message body)

## Sender Details

- **From**: alice@example.com
- **Name**: Alice Smith (if available)
- **Known Contact**: Yes (in whitelist)

## Attachments

- No attachments (OR list if present)

## Suggested Actions

Based on categorization rules:
- High priority: Requires human approval before any action
- Medium priority: Auto-archive after 48 hours of review
- Low priority: Auto-archive immediately after review

## Audit Context

- Detection timestamp: 2026-02-09T14:30:00Z
- Created by: gmail_watcher
- UUID: <auto-generated>
```

## Entity 2: Known Contacts Whitelist

**Purpose**: Configuration data for sender-based email prioritization

**Storage Location**: `config/known_contacts.yaml`

**Format**: YAML array of contact objects

### Schema

```yaml
known_contacts:
  - email: "alice@example.com"
    name: "Alice Smith"
    category: "client"              # Enum: client | internal | vendor | newsletter
    priority_override: "medium"     # Optional: overrides auto-determined priority
    notes: "Key account manager"    # Optional: free-text context

  - email: "noreply@newsletter.com"
    name: "Tech Weekly Newsletter"
    category: "newsletter"
    priority_override: "low"        # Newsletters always set to low
    notes: "Subscribed 2025-01-01"

financial_keywords:                 # Keywords that trigger "financial" category
  - "payment"
  - "invoice"
  - "billing"
  - "transaction"
  - "refund"
  - "subscription"
  - "charges"
  - "receipt"

auto_archive_rules:                 # Optional: auto-action rules (Phase 2+)
  - category: "newsletter"
    after_days: 7
    action: "archive"
```

### Field Definitions

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| email | string | ✅ | Email address to match |
| name | string | ✅ | Human-readable name |
| category | enum | ✅ | Classification (client, internal, vendor, newsletter) |
| priority_override | enum | ❌ | Override auto logic (high, medium, low) |
| notes | string | ❌ | Free-text context |

### Priority Determination Logic

Used by email_categorizer.py:

```
if sender in known_contacts:
    base_priority = known_contacts[sender].priority_override or "medium"
else:
    base_priority = "high"  # Unknown senders default to high

if has_attachments:
    priority = "high"  # Attachments always elevate to high
elif contains_financial_keyword(subject + snippet):
    priority = "high"  # Financial emails always high
else:
    priority = base_priority

return priority
```

## Entity 3: Email Execution Confirmation File

**Purpose**: Record that an email action was executed and the result

**Storage Location**: `AI_Employee_Vault/In_Progress/<timestamp>_<message_id>_confirmation.md`

**Created By**: approved_watcher after executing email action

### YAML Frontmatter Schema

```yaml
---
type: email_confirmation            # Literal: "email_confirmation"
gmail_message_id: "18d4f3a2b1c9e7f6" # Original message ID
action_type: "archive"              # Enum: archive | mark_as_read
status: "success"                   # Enum: success | failed | error
execution_timestamp: "2026-02-09T14:30:45Z"  # When action executed
error_message: null                 # Error description if status != success
error_code: null                    # Error code if status != success (NOT_FOUND, AUTH_ERROR, etc.)
mcp_response:                       # Full response from MCP server
  status: "success"
  action: "archived"
  message_id: "18d4f3a2b1c9e7f6"
  timestamp: "2026-02-09T14:30:45Z"
---
```

### Markdown Body

```markdown
## Action Summary

- **Original Message**: alice@example.com - "Project update"
- **Action Type**: Archive
- **Status**: ✅ Success
- **Execution Time**: 2026-02-09 14:30:45 UTC

## Result

- Message archived in Gmail
- Original file moved from Approved/ to In_Progress/
- Confirmation persisted for audit trail

## Next Steps

- Manually move this file to Done/ when task is complete
- Or system will auto-archive after 7 days
```

## Entity 4: Audit Log Entry

**Purpose**: Append-only record of all Gmail integration events for audit trail

**Storage Location**: `AI_Employee_Vault/Logs/<YYYY-MM-DD>.json`

**Format**: NDJSON (one JSON object per line, no arrays)

### Schema

```json
{
  "timestamp": "2026-02-09T14:30:00Z",
  "event_type": "email_detected",
  "actor": "gmail_watcher",
  "target": "FILE_alice_project-update.md",
  "message_id": "18d4f3a2b1c9e7f6",
  "sender": "alice@example.com",
  "subject": "Project update for Q1",
  "priority": "high",
  "status": "success",
  "error_code": null,
  "error_message": null,
  "context": {
    "watcher_instance": "gmail_watcher_v1",
    "poll_interval": 120,
    "quota_calls_today": 42,
    "is_duplicate": false
  }
}
```

### Event Types & Fields

**email_detected** (emitted by gmail_watcher:T017):
- timestamp, event_type, actor, target, message_id, sender, subject, priority, status, context

**email_approved** (emitted by status_field_watcher):
- timestamp, event_type, actor, target, message_id, old_status, new_status, status

**email_executed** (emitted by approved_watcher:T033):
- timestamp, event_type, actor, target, message_id, action_type, status, error_code, mcp_response

**email_archive_attempt** (emitted by gmail_mcp_server:T029):
- timestamp, event_type, actor, message_id, status, error_code, mcp_tool_result

**email_mark_read_attempt** (emitted by gmail_mcp_server:T029):
- timestamp, event_type, actor, message_id, status, error_code, mcp_tool_result

## Relationships

```
Email Action File (1)
  ├─ sender → Known Contacts (0..1)
  ├─ gmail_message_id ← Email Execution Confirmation (0..1)
  └─ audit events ← Audit Log (0..n)

Known Contacts Whitelist (1)
  └─ used_by ← email_categorizer for priority calculation

Email Execution Confirmation (1)
  └─ gmail_message_id → Email Action File (1)
```

---

## Constraints

1. **Uniqueness**: Each email_message_id appears once per user per account (unique constraint)
2. **Timestamps**: All timestamps must be ISO 8601 UTC (no local times)
3. **Status Values**: Must use exact enum values (no variations)
4. **Priority Levels**: high | medium | low (no other values)
5. **Audit Logging**: Every state change must be logged atomically
